# Local automatic play with reinforcement learning

The automatic-play system currently consists of a local Rust reinforcement
learning environment and an optional Python training/evaluation pipeline. The
Rust engine remains authoritative for game state, action legality, seeded
randomness, and goal status.

This is currently a command-line training and evaluation system. It is not yet
a button in the Tauri game UI. The Makefile's `playtest` target runs the
trained RL player.

## Build the RL environment

From the repository root:

```bash
make rl-build
```

This builds:

```text
src-tauri/target/release/rl_env
```

## Run the dependency-free smoke test

```bash
make rl-smoke
```

The smoke test starts a seeded `gtr2career` simulation and sends actions
through the JSON-lines protocol. It checks that the environment can expose
actions, return observations, and execute a step.

To interact with the environment manually:

```bash
printf '%s\n' \
  '{"op":"actions"}' \
  '{"op":"observation"}' \
  '{"op":"step","action_id":0}' \
  | src-tauri/target/release/rl_env --dataset gtr2career --seed 42
```

## Install the local training dependencies

The Python layer is optional and runs locally:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r rl/requirements.txt
```

The complete setup can also be performed from the Makefile. It creates
`.venv`, installs the dependencies, and builds the Rust environment:

```bash
make playtest-prepare
```

## Train an automatic player

```bash
source .venv/bin/activate
python3 rl/train.py \
  --timesteps 100000 \
  --output rl/models/ppo-baseline
```

The equivalent Make target is:

```bash
make playtest-train \
  RL_GOAL="championships:level=1,count=1" \
  RL_TIMESTEPS=100000 \
  RL_N_STEPS=2048 \
  RL_BATCH_SIZE=64 \
  RL_PROGRESS=1 \
  RL_MODEL=rl/models/ppo-baseline
```

Training uses CPU-based masked PPO. Illegal actions are masked instead of
being silently converted into waiting. Set `RL_PROGRESS=1` to print completed
timesteps, percentage, elapsed time, throughput, and an estimated remaining
time. Adjust the reporting interval with `RL_PROGRESS_INTERVAL=1000`.

The direct Python equivalent is:

```bash
python3 rl/train.py \
  --timesteps 100000 \
  --progress \
  --progress-interval 1000 \
  --output rl/models/ppo-baseline
```

## Evaluate a trained player

```bash
source .venv/bin/activate
python3 rl/evaluate.py \
  --model rl/models/ppo-baseline \
  --episodes 20
```

The complete Makefile evaluation command is:

```bash
make playtest-evaluate \
  RL_MODEL=rl/models/ppo-baseline \
  RL_EPISODES=20
```

Evaluation uses explicit independent seeds so results can be reproduced.

## Run the trained policy as an automatic player

After training a model, run complete local episodes with:

```bash
source .venv/bin/activate
python3 rl/playtest.py \
  --model rl/models/ppo-baseline \
  --episodes 20 \
  --seed 20000 \
  --goal "championships:level=1,count=1" \
  --output rl/data/ppo-playtest.json
```

The complete Makefile workflow can be run explicitly:

```bash
make playtest-prepare
make playtest-train RL_MODEL=rl/models/ppo-baseline
make playtest-evaluate RL_MODEL=rl/models/ppo-baseline
make playtest RL_MODEL=rl/models/ppo-baseline \
  RL_OUTPUT=rl/data/ppo-playtest.json
```

`make playtest` is the single Makefile entry point for running a trained
automatic player:

```bash
make playtest \
  RL_MODEL=rl/models/ppo-baseline \
  RL_EPISODES=20 \
  RL_GOAL="championships:level=1,count=1" \
  RL_OUTPUT=rl/data/ppo-playtest.json
```

The runner uses the Rust legal-action mask on every step, records the action
path and per-step rewards, and prints a summary of goal completion, outcomes,
days, and step counts. Add `--stochastic` to sample from the policy instead of
using deterministic predictions.

The JSON export is an ordered event trace. By default it contains only what the
AI did:

```bash
python3 rl/playtest.py --model rl/models/ppo-baseline \
  --episodes 1 --output rl/data/playtest-actions.json
```

Use `--trace observations` to include the structured engine state seen before
and after every action. Use `--trace decisions` for the deepest export: it also
includes the policy probability of the selected action and a probability-ranked
list of legal alternatives. These probabilities explain the policy's selection
evidence, but are not a generated natural-language rationale or hidden chain of
thought.

## Collect trajectories

Trajectories can be collected for inspection, debugging, or future imitation
learning:

```bash
source .venv/bin/activate
python3 rl/collect.py \
  --episodes 20 \
  --output rl/data/random.jsonl
```

Or:

```bash
make playtest-collect \
  RL_EPISODES=20 \
  RL_OUTPUT=rl/data/random.jsonl
```

## Current scope

The current implementation can prepare dependencies, train, evaluate, collect
trajectories, and run an RL policy locally through Makefile targets. A trained
model is not included in the repository, and the policy is not yet integrated
into the desktop UI.
